# Asteria — 多人联机与持久化

> 状态：Active  
> 首版目标：2–4 人好友房间；房主权威；单机始终可运行。

## 1. 联机产品模型

Asteria 采用“家园存档 + 临时会话”的模式。

- 每个家园星球属于一个存档主人。
- 好友以自己的玩家档案加入房主家园。
- 远征由房主或被授权玩家发起。
- 远征过程中共享目标和世界状态。
- 结束后，房主家园保存公共成果；访客保存个人发现、回忆、外观与可带回奖励。

首版不做大型常驻服务器、公开 MMO 大厅或陌生人匹配。

## 2. 模式

### 2.1 单机

- 所有系统必须支持离线运行。
- AI 星友可以代替部分 Cooperate 需求，但效率较低或操作更简单。
- 存档格式与多人一致，避免两套逻辑。

### 2.2 好友家园访问

- 2–4 人进入房主家园。
- 访客可游览、互动、拍照、参与活动和远征准备。
- 默认不能拆除设施、移动居民住宅或改写关键社区决策。
- 房主可以授权“共同建设者”。

### 2.3 远征会话

- 房主/会话主机拥有世界权威。
- 客户端提交输入和交互请求。
- 主机验证目标、资源与状态变化后广播结果。
- 每个阶段生成恢复点，支持掉线重连。

### 2.4 异步访问（后续）

不要求首版实现。可扩展为：

- 留下礼物、照片和明信片
- 下载只读家园快照参观
- 交换角色模板、装饰蓝图和创作物
- 不运行对方完整居民模拟，避免离线冲突

## 3. 权限模型

| 权限 | 房主 | 共同建设者 | 访客 |
|---|---:|---:|---:|
| 发起远征 | 是 | 可配置 | 请求 |
| 放置临时远征工具 | 是 | 是 | 是 |
| 修改家园大型设施 | 是 | 是 | 否 |
| 移动居民住宅 | 是 | 可配置 | 否 |
| 邀请/移除居民 | 是 | 否 | 否 |
| 触发社区活动 | 是 | 可配置 | 参与 |
| 拍照/赠礼/表情 | 是 | 是 | 是 |
| 确认重大分支 | 最终确认 | 投票 | 投票 |

重大分支使用“队伍投票 + 房主最终确认”，并在 UI 中明确，不允许静默覆盖。

## 4. 网络所有权

### 4.1 主机权威对象

- 星球时间与天气
- POI 与事件状态
- 远征目标
- 星友和生物 AI
- 可放置工具
- 公共资源
- 家园设施与居民关系变更
- 远征结算

### 4.2 客户端预测/本地表现

- 本地玩家移动输入与相机
- 纯表现动画、粒子、声音
- UI 展开状态
- 照片预览
- 非关键环境摆动

玩家移动可做轻量客户端预测与主机校正，但首版优先稳定和低人数，不追求竞技级延迟模型。

## 5. 同步优先级

| 层级 | 数据 | 频率 |
|---|---|---|
| 高频 | 玩家位置、旋转、移动状态 | 10–20 Hz + 插值 |
| 中频 | 星友/生物位置、天气参数、工具状态 | 2–10 Hz |
| 事件 | Observe、Restore、Cooperate、关系变化 | 可靠事件 |
| 快照 | 场景、POI、事件阶段、公共资源 | 加入/重连/阶段切换 |
| 持久化 | 家园、居民、回忆、发现 | 检查点与会话结束 |

不要同步纯视觉散布物的每个 Transform。球面装饰应由相同 seed 在各端生成，或作为静态场景内容。

## 6. 球面移动网络注意事项

- 权威位置使用世界坐标，同时保存 `planetId`。
- 玩家 `up` 由权威星球中心实时计算，不直接同步完整重力向量。
- 插值后重新投影/校正角色朝向，避免跨极点时逐帧翻转。
- 传送、救援和重生使用球面方向 + 地表高度，而非只保存平面坐标。
- 远距离队友方向应基于大圆最短路径，不使用普通屏幕方位假设。

## 8. 保存策略

- 家园关键操作后增量保存。
- 远征在阶段切换、关键 Restore 和主动撤离时写检查点。
- 会话结束生成一次原子结算，避免奖励重复。
- 存档写临时文件后再替换正式文件。
- 每次 schema 变更提供迁移函数和备份。
- 不把 Unity Scene/Prefab 序列化数据直接当作用户存档。

## 9. 掉线与重连

### 玩家掉线

1. 角色进入短时安全跟随状态。
2. 30–60 秒内可重连原席位。
3. 超时后角色由信标回收，工具和关键发现留在公共状态。
4. 重新加入时获取最近权威快照。

### 主机掉线

首版：

- 尝试保存最后检查点。
- 会话结束，所有玩家回到个人菜单。
- 访客保留已经确认的个人发现。

主机迁移属于后续能力，不阻塞第一个可玩版本。

## 10. 联机技术选择门槛

当前仓库只有 Multiplayer Center，没有运行时 Netcode。

进入联机阶段时优先验证 Netcode for GameObjects，验证项：

- Unity 6 / 当前 URP 版本兼容
- Host + 1 Client 在球面极点移动稳定
- NetworkTransform 是否适合自定义 `up`
- 场景内大量静态散布不产生网络开销
- 断线重连和快照恢复是否可控

若默认 NetworkTransform 不满足球面朝向，编写专用 `SphericalNetworkTransform`，不要因此重写本地运动核心。

## 11. 安全与社交控制

联网前必须具备：

- 好友/邀请制房间
- 踢出与封禁
- 文本/用户创作内容过滤
- 屏蔽玩家后隐藏其语音、文本和创作物
- 家园修改权限清晰可见
- 会话操作审计（谁移动/删除了什么）

首版不内置开放语音。优先使用表情、快捷语句和平台好友语音。

## 12. 首个联机验收

- Host + Client 可在 `SphereMoveDemo` 上连续移动 10 分钟。
- 双方可穿越极点与星球背面，远端角色无明显翻转爆跳。
- Observe 由主机确认且双方只解锁一次。
- 放置 3 个信标并正确同步上限。
- 客户端掉线后 30 秒内重连，恢复位置与事件状态。
- 单机模式不依赖网络包即可正常 Play。
