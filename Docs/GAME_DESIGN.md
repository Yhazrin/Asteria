# Asteria

## A Multiplayer Spherical Exploration Game

---

# 0. 你的身份

你现在是一名：

* Unity 6 高级游戏工程师
* 技术美术工程师
* 游戏系统架构师
* 多人联机开发工程师

负责基于当前 Unity 项目开发一款独立游戏。

你必须遵守以下原则：

1. 不要一次性开发完整游戏。
2. 每次修改前必须理解当前项目结构。
3. 优先实现可运行的垂直切片。
4. 不允许为了增加内容而破坏核心体验。
5. 不允许把项目演变成传统生存沙盒。

---

# 1. 项目概念

## 游戏名称

Asteria

## 类型

多人联机球形探索游戏。

## 核心描述

> 玩家来到一颗微型星球，在它的表面自由漫游，与环境、生物和其他玩家相遇，发现隐藏在星球上的故事，并留下属于自己的痕迹。

这不是一个战争世界。

这不是一个资源竞争世界。

这不是一个建造游戏。

这是一个关于：

* 探索
* 相遇
* 发现
* 记录
* 陪伴

的游戏。

---

# 2. 核心体验循环

游戏循环：

```
探索未知区域

↓

发现特殊地点

↓

与环境互动

↓

获得新的观察方式

↓

记录发现

↓

留下自己的痕迹

↓

继续前往新的地方
```

玩家成长不是为了变强。

玩家成长是：

> 看见更多世界。

# 3. 与传统沙盒游戏的区别

禁止设计：

不要：

* 挖矿
* 合成
* 生存值
* 饥饿
* 饮水
* 大型基地

---

## 不做 MMO

不要：

* 等级排行榜
* 装备数值
* 战斗职业

* 日常任务

---

## 不做竞技游戏

不要：

* PVP
* 排位
* 击杀
* 竞争资源

---

# 4. 世界设计

## 星球结构

整个世界是一颗球。

玩家真正生活在球体表面。

不是：

```
平面地图 + 球形贴图
```

而是：

```
真实球面世界

        玩家

          ↑
       法线方向

       🌍
```

---

## 球形世界必须实现

玩家：

* 永远受到星球中心方向重力影响
* 可以绕星球完整移动
* 可以经过南北极
* 可以走到星球背面
* 可以看到真实地平线变化

---

# 5. 第一阶段世界规模

不要制作巨大开放世界。

第一阶段：

制作一颗：

```
直径 500-1000 米
```

的小型星球。

重点：

证明：

> 一颗球也可以成为一个完整世界。

# 6. 第一颗星球

包含三个区域。

---

## 风之草原

特点：

* 开阔
* 风吹动植物
* 适合奔跑
* 可以滑翔

互动：

* 风车
* 风铃
* 飞行生物

---

## 雾林

特点：

* 光线柔和
* 视野有限
* 声音导航

互动：

* 发光植物
* 古树
* 隐藏路径

---

## 星砂谷

特点：

* 夜晚出现变化
* 地面出现光路

互动：

* 古老观测设备
* 星象机关
* 天象事件

---

# 7. 玩家角色

第一阶段：

第三人称角色。

必须实现：

* WASD移动
* 跳跃
* 奔跑
* 镜头旋转

---

## 球面移动技术要求

角色移动：

不是：

```
Vector3.up = 世界Y轴
```

而是：

```
gravityDirection =
(player.position - planet.center).normalized
```

角色：

```
up direction = gravityDirection
```

---

必须解决：

* 球面旋转
* 角色朝向
* 摄像机跟随
* 极点翻转
* 背面移动

---

# 8. 摄像机系统

第三人称。

要求：

* 平滑跟随
* 鼠标控制
* 自动保持水平感
* 不穿透地形
* 球面旋转稳定

推荐：

Unity Cinemachine。

---

# 9. 核心互动系统

不要设计复杂背包。

互动主要分三类。

---

# Observe

观察。

例如：

玩家靠近：

* 植物
* 动物
* 遗迹

触发：

* 镜头变化
* 声音
* 图鉴记录
* 环境变化

---

# Restore

修复。

例如：

玩家找到损坏的装置。

修复后：

* 点亮灯塔
* 打开道路
* 改变环境

---

# Cooperate

合作。

多人共同完成。

例如：

两个玩家：

分别站在星球两侧。

同时激活装置。

触发：

全球极光。

---

# 10. 玩家痕迹系统

玩家可以留下：

* 小灯
* 路标
* 照片
* 观察记录
* 临时营地

但是：

禁止无限堆放。

必须：

* 数量限制
* 自动管理
* 不影响世界

必须先：

1. 阅读当前代码。
2. 分析影响范围。
3. 输出修改计划。

修改后：

必须报告：

```
修改文件:

新增功能:

测试方式:

下一步:
```

* 大规模重构
* 删除文件
* 引入未知插件
